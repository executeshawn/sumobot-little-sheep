# Glossary — Heatseeker Sumobot

Concise engineering definitions for the terms used across
[`SFG_Report.md`](SFG_Report.md),
[`Control_System_Analysis.md`](Control_System_Analysis.md),
[`Presentation_Outline.md`](Presentation_Outline.md), and
[`Test_Plan.md`](Test_Plan.md). Wording is intentionally short and
oral-defense friendly: each entry gives a plain-English statement, then
the technical formulation, then how the term shows up in this project.

---

### PID — Proportional–Integral–Derivative controller
A controller that adds three corrective terms: one proportional to the
current error, one proportional to its accumulated history, and one
proportional to its rate of change.
Control law: `u(t) = Kp·e + Ki·∫e dt + Kd·de/dt`.
**In this project:** the planned inner loop that will replace the
current fixed-PWM motor commands once an encoder or IMU is fitted.

### FSM — Finite-State Machine
A model in which the system is always in exactly one of a finite set of
states, and transitions between states occur only on defined events.
**In this project:** the seven-state supervisory controller (`IDLE →
CALIBRATE → COUNTDOWN → SEARCH → ATTACK → EVADE → STOP`) in
[`strategy.cpp`](../src/strategy.cpp).

### Transfer Function
The Laplace-domain ratio of an LTI system's output to its input, with
all initial conditions taken as zero: `H(s) = Y(s)/U(s)`. It compactly
captures the system's frequency-response behaviour.
**In this project:** `T(s) = G(s)/(1 + G(s))` derived in
[`SFG_Report.md`](SFG_Report.md) §5 for the planned closed-loop heading
control.

### Mason's Gain Formula
A closed-form rule for the overall transfer function of a signal flow
graph:
`T = (1/Δ)·Σ Pk·Δk`, where `Pk` are forward-path gains, `Δ` is the
graph determinant (built from individual loops and non-touching loop
products), and `Δk` is `Δ` evaluated on the sub-graph not touching `Pk`.
**In this project:** applied in [`SFG_Report.md`](SFG_Report.md) §5
to reduce the heading control SFG to its single closed-loop transfer
function.

### Disturbance Rejection
A closed-loop system's ability to suppress the effect of unmeasured
external inputs (disturbances) on its output. Quantified by the
transfer function `Y(s)/D(s)` evaluated at the relevant frequencies.
**In this project:** linear rejection comes from the PID integrator
(future), and non-linear rejection comes from the EVADE override that
pre-empts the inner loop on any edge event.

### Sensor Fusion
Combining data from two or more sensors to produce an estimate that is
more accurate, more reliable, or richer than any single sensor could
provide on its own.
**In this project:** six VL53L0X channels combined into a single
opponent-bearing decision, plus the priority hierarchy
*edge > front ToF > side/rear ToF*.

### Continuous Ranging
A sensor operating mode in which the device autonomously and repeatedly
performs measurements in the background; the host reads the most recent
result rather than triggering each measurement. Replaces the slower
*one-shot / on-demand* mode.
**In this project:** VL53L0X sensors are configured with
`startRangeContinuous()` at boot; `pollFront()` / `pollSide()` harvest
results without blocking the FSM.

### Closed-Loop Control
Any control structure that *measures* the output, compares it to a
reference, and acts on the resulting error. Equivalent to "feedback
control."
**In this project:** the target architecture described by the SFG. The
outer loop (ToF → reference) is closed today; the inner loop (encoder /
IMU → PID) is provisioned but not yet physically closed.

### Open-Loop Control
Issuing commands without measuring or correcting based on the output —
the actuator simply follows the input. Sensitive to model error and
disturbances, but cheap and easy to implement.
**In this project:** the current motor commands are open-loop fixed-PWM
values selected by the FSM, pending the encoder/IMU upgrade.

### PWM — Pulse-Width Modulation
A way of encoding an analog-like signal level using the *duty cycle*
(on-time fraction) of a fixed-frequency square wave. Average voltage
delivered ≈ `Vsupply × duty`.
**In this project:** generated by the ESP32-S3 LEDC peripheral at 5 kHz
/ 8-bit (256 duty steps) on GPIO 4 and GPIO 7, into the TB6612FNG's
PWMA/PWMB inputs.

### Latency
The time delay between a stimulus (input, event, or command) and the
corresponding observable effect (output, response, or action). Often
characterised by its worst-case value, not its average.
**In this project:** the most safety-critical latency is *edge → motor
reverse*, with a target worst-case ≤ 20 ms; see
[`Test_Plan.md`](Test_Plan.md) §6.

### Polling
Periodically reading a device or signal at a fixed cadence, rather than
reacting to an interrupt or event. Trades a small amount of CPU time
for predictable, easy-to-reason-about timing.
**In this project:** edge sensor polled every 8 ms, front ToF every
30 ms, side/rear ToF every 90 ms — see `config.h`.

### Non-blocking architecture
A software design in which no routine is allowed to hold the main loop
waiting on a slow operation; long operations are run in the background
or split across multiple loop iterations.
**In this project:** the FSM tick reads only cached sensor data; the
expensive operations (VL53L0X ranging, QTR RC discharge timing) either
run on the sensor's own hardware or in short, bounded fast-loop polls.

### RC reflectance sensing
A measurement technique used by Pololu QTR-RC arrays: the host briefly
drives an output capacitor to a known high level, then releases the
line and times how long it takes the line to fall through a logic
threshold. The discharge current is controlled by a phototransistor
illuminated by an IR emitter — a more reflective surface conducts more,
giving a shorter discharge time.
**In this project:** used in `Edge::poll()` at 8 ms cadence for ring
edge detection; readings are normalised to 0..1000 after calibration.

### Edge detection
In the sumobot context, identifying the boundary between the black
dohyo mat and the white ring border. The transition serves as the
"do not cross" signal that overrides every other behaviour.
**In this project:** implemented on the QTR-MD-03RC array; a calibrated
reading below `EDGE_THRESHOLD` (= 250 / 1000) on any of the three
channels declares an edge.

### Stability
A system is *stable* if every bounded input produces a bounded output
(BIBO stability). For an LTI closed-loop system this is equivalent to
all poles of the closed-loop transfer function lying strictly in the
open left half of the complex plane.
**In this project:** verified analytically via the Routh–Hurwitz
criterion on the characteristic polynomial from
[`SFG_Report.md`](SFG_Report.md) §6, and empirically by checking that
no sustained oscillation occurs after Ziegler–Nichols PID tuning.

### Overshoot
The amount by which a system's output exceeds its final steady-state
value in response to a step input, usually expressed as a percentage of
that final value. A second-order rule of thumb relates overshoot to
the damping ratio `ζ`.
**In this project:** the design target is overshoot ≤ 15 % in the
heading-control step response — sufficient for fast manoeuvres without
losing wheel traction; see [`Test_Plan.md`](Test_Plan.md) §10.

### Settling time
The time required for the system's response to enter, and remain
within, a specified tolerance band of its final value (commonly ±2 %
or ±5 %). It quantifies how quickly the controller "lets go" of the
transient and tracks the new reference.
**In this project:** the post-tuning target is a 2 % settling time of
five motor time-constants (5·τm ≈ 250 ms for the assumed τm = 50 ms).
